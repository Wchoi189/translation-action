Add OpenRouter and Upstage AI providers for LLM-based translation

This commit adds two new translation providers that leverage large language
models (LLMs) for high-quality translations, especially suitable for
documentation like README.md files.

## New Providers

### OpenRouter Provider
- Identifier: `openrouter`
- Uses OpenRouter API to access multiple LLM models
- Default model: `openai/gpt-3.5-turbo` (configurable via api_additional_parameter)
- Supports any language pair available in the selected model
- Language format: `from-to` (e.g., `en-uk`)

### Upstage Provider
- Identifier: `upstage`
- Uses Upstage AI's Solar models via custom API endpoint
- Base URL: `https://api.upstage.ai/v1/chat/completions`
- Default model: `solar-pro2` (configurable via api_additional_parameter)
- Language format: `from-to` (e.g., `en-ko`)

## Benefits

1. **Higher Quality Translations**: LLM-based translation provides better
   context-aware translations compared to free APIs
2. **Documentation-Optimized**: Special prompts preserve Markdown formatting,
   code blocks, and links
3. **Flexible Model Selection**: Users can choose models based on quality/cost
   tradeoffs
4. **Future-Proof**: As new models are added to OpenRouter/Upstage, they
   become available automatically

## Usage

```yaml
- uses: YOUR_USERNAME/translation-action@main
  with:
    provider: upstage  # or openrouter
    lang: en-ko
    source: README.md
    api_key: ${{ secrets.UPSTAGE_API_KEY }}
    api_additional_parameter: solar-pro2  # optional
```

## Notes

- Both providers require API keys (stored as GitHub Secrets)
- OpenRouter charges per token (input + output)
- Upstage uses custom API endpoint with Solar models
- Language codes use hyphen separator (`en-ko`, `en-uk`, etc.)
